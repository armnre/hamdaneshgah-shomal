## ۲. معماری (تفاوت با پشته پیشنهادی)
محیط اجرا Zite است: Frontend با React + Vite + Tailwind، Backend با اندپوینت‌های تایپ‌شده (`src/api/*.ts`, اعتبارسنجی Zod سمت سرور)، پایگاه داده مدیریت‌شده Zite (PostgreSQL) با کلید خارجی (لینک‌ها). Next.js، NestJS، Prisma، Docker و Nginx در این محیط قابل اجرا نیستند و **فایل‌های Docker/استقرار شخصی تولید نشده‌اند**. استقرار از طریق «Publish» در Zite با HTTPS انجام می‌شود.

جداول: Faculties، Majors، Associations، Categories، News، Events (نوع: رویداد/همایش/دوره/فراخوان)، Media Assets، Admin Members، Audit Logs، Site Settings، Contact Messages.

## ۳. امنیت و مجوزها
- ورود با لینک یک‌بارمصرف ایمیلی (بدون رمز ذخیره‌شده).
- تمام اندپوینت‌های مدیریتی `authenticated: true` و بررسی نقش سمت سرور (`src/lib/server.ts`).
- نقش‌ها: مدیر کل (همه بخش‌ها)، ویراستار محتوا (اخبار، رویداد، دسته، رسانه، پیام)، مدیر انجمن (فقط انجمن خود و اخبار/رویدادهای آن).
- راه‌اندازی اولیه: فقط وقتی هیچ مدیری وجود ندارد، اولین کاربر واردشده می‌تواند مدیر کل شود.
- SQL فقط با پارامتر؛ Markdown بدون HTML خام رندر می‌شود (ضد XSS).
- همه ایجاد/ویرایش/حذف‌ها در Audit Logs ثبت می‌شوند. فرم تماس: honeypot + محدودیت ۳ پیام در ساعت برای هر ایمیل.
- پنل مدیریت `noindex`.

## ۴. تاریخ‌ها
ذخیره به‌صورت ISO/UTC؛ نمایش شمسی با `Intl` (تقویم persian، منطقه Asia/Tehran).

## ۵. طرح ماژول انتخابات (فاز دو — پیاده‌سازی‌نشده)
جداول پیشنهادی: Elections، Candidates، Eligible Voters (از ورود اکسل با پیش‌نمایش و گزارش خطای ردیفی)، Voter Participation (فقط «رأی داده/نداده»)، Ballots (بدون شناسه رأی‌دهنده). جلوگیری از رأی تکراری با upsert روی (انتخابات، رأی‌دهنده) و مدل تهدید و آزمون امنیتی مستقل پیش از استفاده.

## ۶. محدودیت‌های شناخته‌شده
تست خودکار واحد/E2E نوشته نشده است؛ sitemap/robots اختصاصی در این محیط تولید نشده است؛ پشتیبان‌گیری از طریق قابلیت Backups پایگاه داده Zite انجام می‌شود.
