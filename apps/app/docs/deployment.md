# راهنمای استقرار

دو مسیر استقرار وجود دارد:

| مسیر | ورود مدیران | توضیح |
|---|---|---|
| Zite (apps/app) | صفحه‌ی ورود خود پلتفرم Zite | صفحه‌ی ورود Zite انگلیسی است. تغییر عنوان و متن آن (`authentication.authPage`) فقط در پلن Business ممکن است و حتی آن‌وقت هم فقط عنوان و زیرعنوان را عوض می‌کند، نه زبان یا ساختار صفحه را. ورود فارسی کامل در Zite ممکن نیست. |
| Netlify + Neon (deploy/) | صفحه‌ی فارسی `/admin/login` با پیوند ایمیلی (Resend) | مسیر توصیه‌شده برای استقرار رسمی. |

صفحات عمومی (`/`، `/elections`، `/vote`، `/structure` و …) در هیچ‌کدام از این دو مسیر به ورود نیاز ندارند. اندپوینت‌های `castVote`، `listPublicElections` و `getStructure` بدون `authenticated` تعریف شده‌اند.

## Netlify — گام به گام

1. یک پایگاه داده‌ی Postgres در Neon بسازید و رشته‌ی اتصال آن (pooled، با `sslmode=require`) را بردارید.
2. در Netlify گزینه‌ی «Add new site ← Import from Git» را بزنید و این مخزن را انتخاب کنید. تنظیمات build از `netlify.toml` خوانده می‌شود (`base = deploy`، `publish = dist`).
3. در بخش Site configuration ← Environment variables این متغیرها را تعریف کنید. همه‌ی آن‌ها فقط سمت سرور هستند و هیچ‌کدام نباید با پیشوند `VITE_` تعریف شود:

| متغیر | الزامی | توضیح |
|---|---|---|
| `DATABASE_URL` | بله | رشته‌ی اتصال Neon |
| `SESSION_SECRET` | بله | دست‌کم ۳۲ نویسه‌ی تصادفی، مثلاً خروجی `openssl rand -base64 48` |
| `RESEND_API_KEY` | بله | کلید Resend برای ارسال پیوند ورود |
| `MAIL_FROM` | بله | فرستنده‌ی تأییدشده در Resend، مثل `هم‌دانشگاهی <no-reply@your-domain>` |
| `ZITE_BOOTSTRAP_ADMIN_EMAILS` | فقط برای راه‌اندازی اول | ایمیل(های) مجاز برای ثبت مدیر کل اولیه، جداشده با ویرگول |
| `SITE_URL` | بله | نشانی نهایی سایت، مثل `https://example.ac.ir` (بدون `/` پایانی) |
| `ZITE_VOTER_PEPPER` | پیش از هر Import یا رأی | کلید محرمانه‌ی HMAC برای هش کد ملی، دست‌کم ۳۲ نویسه‌ی تصادفی (مثلاً `openssl rand -base64 48`). نام قدیمی `VOTER_PEPPER` هم برای سازگاری خوانده می‌شود، ولی از همین نام استفاده کنید. نبودِ آن ⇐ Import و رأی رد می‌شوند. تغییر آن هش‌های قبلی را بی‌اعتبار می‌کند و فهرست‌ها باید دوباره Import شوند. |

4. مایگریشن‌ها هنگام build به‌طور خودکار اجرا می‌شوند (`node scripts/migrate.mjs` که از `DATABASE_URL` استفاده می‌کند). برای اجرای دستی:
   ```
   cd deploy && npm ci && DATABASE_URL=... npm run migrate
   ```
5. Deploy کنید.

## اولین ورود مدیر کل

1. مطمئن شوید ایمیل شما در `ZITE_BOOTSTRAP_ADMIN_EMAILS` آمده است.
2. به `/admin` (یا `/login` یا `/signin`) بروید. به `/admin/login` هدایت می‌شوید.
3. ایمیل را وارد کنید. پیوند ورود ۱۵ دقیقه و فقط یک بار معتبر است. پس از ورود به همان صفحه‌ای برمی‌گردید که از آن آمده بودید.
4. چون هنوز مدیری تعریف نشده، دکمه‌ی «ثبت من به‌عنوان مدیر کل» نمایش داده می‌شود. این دکمه فقط برای ایمیل‌های فهرست‌شده نمایش داده می‌شود و سرور هم همین را دوباره بررسی می‌کند. بعد از ثبت اولین مدیر، این گزینه برای همیشه بسته می‌شود.
5. کاربرانی که نقشی ندارند صفحه‌ی «دسترسی مدیریتی ندارید» را می‌بینند.
6. پس از راه‌اندازی، `ZITE_BOOTSTRAP_ADMIN_EMAILS` را می‌توانید حذف کنید.

## Zite

- Secretها از بخش Settings ← Secrets تعریف می‌شوند: `ZITE_BOOTSTRAP_ADMIN_EMAILS` و `ZITE_VOTER_PEPPER` (همان نام در Netlify).
- در Zite تراکنش و قید یکتای دیتابیسی در اختیار نیست؛ برای رأی‌گیری رسمی از Netlify + Neon استفاده کنید (جزئیات: security.md).
- ورود مدیران با صفحه‌ی پلتفرم انجام می‌شود و پس از آن کاربر به `/admin` برمی‌گردد.
- دامنه‌ی داخل `robots.txt` و `sitemap.xml`: «نیازمند تعیین دامنه‌ی واقعی».
