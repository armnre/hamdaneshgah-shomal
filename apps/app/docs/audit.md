## ۲. UI/UX و واکنش‌گرایی
- راست‌چین: `dir="rtl"` در ریشه، فونت وزیرمتن. **[بررسی کد]**
- **مشکل (اولویت متوسط):** ۲۹ کلاس جهت‌دار فیزیکی (`ml-/mr-/pl-/pr-/left-/right-`) در کد هست که در RTL ممکن است جای اشتباه بنشیند؛ باید به `ms-/me-/ps-/pe-/start-/end-` تبدیل شوند.
- منوی موبایل سایت و Sheet کشویی پنل وجود دارد؛ ۷۷ نقطه شکست `sm/md/lg`. **[بررسی کد]**
- **مشکل (اولویت متوسط):** باندل JS بالای ۵۰۰KB (پنل و سایت در یک chunk) — کندی بارگذاری اول در موبایل. راه‌حل: lazy-load کردن `/admin`. **[آزمایش‌شده: هشدار build]**
- **مشکل (اولویت پایین):** صفحات بدون تصویر واقعی فقط الگوی گرافیکی دارند؛ پس از ورود محتوای واقعی باید دوباره بازبینی شود.
- **بررسی بصری در موبایل کوچک/بزرگ/تبلت/لپ‌تاپ: [تأییدنشده].** در محیط ساخت مرورگر (Chromium/Playwright) نصب نیست، پس اسکرین‌شات یا تست E2E اجرا نشد. باید با پیش‌نمایش Zite در عرض‌های 360/414/768/1280 دستی بررسی شود.

## ۴. پایگاه داده
- پایگاه داده مدیریت‌شده Zite است (مبتنی بر PostgreSQL طبق مستندات پلتفرم). دسترسی مستقیم وجود ندارد: `SELECT version()` رد شد (`Function "version" is not allowed`). **[آزمایش‌شده]** — یعنی نسخه و پیکربندی واقعی PostgreSQL قابل تأیید نیست.
- SQL فقط خواندنی است؛ تغییرات ساختار از طریق ابزار Schema پلتفرم انجام می‌شود. **Migration فایل‌محور (مثل Prisma) وجود ندارد**؛ تاریخچه ساختار در `.zite/db.ts` و `zite.lock` منعکس است.
- پشتیبان‌گیری: پلتفرم Backup دستی و بازیابی نقطه‌ای دارد (از رابط کاربری). در این ممیزی هیچ داده‌ای حذف نشد، پس نیاز به Backup نبود. **پیشنهاد:** پیش از انتشار یک Backup نام‌دار بسازید.
- انتقال داده: از طریق SDK/اسکریپت می‌توان همه جداول را به JSON/CSV خواند (همین ممیزی شمارش‌ها را خواند). خروجی کامل JSON تولید و بازیابی آن در Postgres دیگر **[تأییدنشده]**.

## ۵. استقلال از Zite و استقرار روی Linux
| لایه | وضعیت |
|---|---|
| کد فرانت‌اند (React/Vite) | قابل build است **[آزمایش‌شده]**؛ اما به ماژول‌های `zitejs/api`، `zitejs/auth`، `zitejs/upload` وابسته است |
| Backend (۱۸ اندپوینت) | روی Worker پلتفرم اجرا می‌شود؛ وابسته به `zitejs/backend` و `zitejs/db` (۱۷ فایل). اجرای مستقل بدون بازنویسی لایه داده/احراز هویت **ممکن نیست** |
| احراز هویت | لینک ایمیلی مدیریت‌شده Zite؛ جایگزین مستقل لازم دارد |
| پایگاه داده | مدیریت‌شده؛ dump مستقیم PostgreSQL در دسترس نیست؛ فقط خروجی از طریق API |
| آپلود فایل | فضای ذخیره‌سازی Zite؛ URLها پس از خروج باید منتقل شوند |

**نتیجه:** پروژه در وضعیت فعلی **قابل استقرار مستقل روی سرور Linux نیست** و هیچ آزمایش انتقالی موفقی انجام نشده. کد را می‌توان از طریق GitHub (متصل) خروجی گرفت، اما برای اجرا باید سه لایه بازنویسی شود: دسترسی داده (مثلاً Prisma/Drizzle روی Postgres خودتان)، احراز هویت (مثلاً better-auth/Auth.js) و آپلود (S3/MinIO). منطق مجوزها اکنون در `src/lib/policy.ts` بدون وابستگی به پلتفرم جدا شده تا در انتقال قابل استفاده مجدد باشد.

## ۶. تست‌ها
- **واحد [آزمایش‌شده]:** `npm test` → ۷ از ۷ موفق (ماتریس نقش، چهار سناریوی راه‌اندازی مدیر کل، محدودیت رسانه، slug فارسی).
- typecheck و build: موفق. **[آزمایش‌شده]**
- **یکپارچه و E2E: اجرا نشد.** مرورگر در محیط نیست و اندپوینت‌ها فقط داخل runtime پلتفرم قابل فراخوانی‌اند. پیشنهاد: پس از انتشار، Playwright روی URL منتشرشده از ماشین خودتان.

## ۸. مسیر پیشنهادی
- **اگر ماندن روی Zite قابل قبول است:** موارد ۲ تا ۹ را انجام دهید، سپس ماژول انتخابات.
- **اگر استقرار مستقل الزامی است:** قبل از انتخابات تصمیم بگیرید؛ هرچه کد بیشتر شود، مهاجرت گران‌تر است. انتخابات به‌ویژه به احراز هویت و یکپارچگی داده حساس است.
